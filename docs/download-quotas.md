# 群聊规则下载限额

在「新建规则 / 编辑规则」中启用「下载容量限额」，添加一个或多个周期与容量。
例如每小时 2 GB、每天 10 GB、每月 100 GB，三个条件必须同时满足。
旧规则默认不限额，不需要手动迁移；启动新版后会自动补齐 SQLite 字段和账本表。

## 周期与容量

| 配置 | 恢复时间 |
| --- | --- |
| 每小时 | 下一个整点 |
| 每天 | 次日零点 |
| 每周 | 下周一零点 |
| 每月 | 下月 1 日零点，按自然月计算 |
| 自定义每 N 小时 / 天 | 从首次保存配置的固定起点分段计算，普通保存不会重置起点 |

默认时区为北京时间 `Asia/Shanghai`，界面同时显示时区和下次恢复时间。
容量使用 1024 进制：1 MB = 1024² 字节，1 GB = 1024 MB，1 TB = 1024 GB。
界面支持小数容量；内部统一保存整数文件大小。

## 按完整文件准入

开始下载前，必须同时满足每一项限额：

```text
已完成的用量 + 正在下载的预占容量 + 本文件大小 <= 周期限额
```

例如每天限额 100 MB，已经使用 90 MB：

- 20 MB 文件整笔等待，尚未开始传输，不会下载到一半因限额中断。
- 后面的 5 MB 文件可以下载；恰好为 10 MB 的文件也可以下载。
- 其他规则独立使用自己的额度。
- 已开始的文件会完整下载，不因跨过零点或降低限额而被额度功能截断。

同规则的实时监控、历史下载、遗漏回补和评论下载共用额度。
媒体组按其中每个媒体文件分别判断，不要求整个相册同时准入。
消息文本导出不计入媒体限额；Bot 直接下载任务也不使用群聊规则的额度。

## 预占、结算与恢复

领取下载并发槽位、检查额度、预占整个文件容量在同一 SQLite 写事务中完成。
多个下载竞争额度时不会超分配；重复点击恢复或重试不会重复启动同一任务。
因全局并发满而等待的任务尚不预占额度。

下载成功后，预占转为已用量，用量归属开始预占时的周期。
这里计算成功文件的逻辑容量，不累计失败重传消耗的网络流量。
失败、取消、暂停和删除未完成任务会释放预占；删除成功记录或文件不会退还已用量。

跨周期仍在下载的文件保留预占，直到完成或停止。
提高或降低容量会影响后续任务，不打断现有下载；新增限额也会计入当时正在下载的文件。
修改已有限额时保留该条目的 ID、周期起点与历史账本。
移除限额条目后它不再限制下载，历史账本仍保留。

等待额度的任务仍为 `queued`，单独记录 `queue_reason=quota`、具体原因和下次评估时间，
不占下载并发槽位。后台调度器至少每 30 秒检查一次，周期恢复后自动继续；
失败释放额度或修改限额后也会重新调度，不依赖新消息或其他下载完成。
等待任务支持暂停、恢复、置顶和删除；置顶不能绕过额度检查。

单个文件超过某个周期的总容量时，任务显示失败并提示修改限额。
提高上限后可点击重试，不会定时反复请求无法容纳的文件。
文件大小无法获取时会补查 Telegram 元数据，仍未知则等待并显示原因，默认一小时后再查，
不会把未知大小当作 0 字节免费准入。

服务重启保留已用量和未完成预占，并恢复所有未完成任务，不受下载历史最近 1000 条的限制。
重启前遗留状态会在启动 Telegram 监听前重置，避免把刚创建的实时下载重复调度。

## API

创建和编辑仍使用 `POST /api/group-rules`、`PUT /api/group-rules/{id}`。
新增字段示例：

```json
{
  "quota_enabled": true,
  "quota_limits": [
    {"period": "hour", "limit_value": 2, "limit_unit": "GB"},
    {"period": "day", "limit_value": 10, "limit_unit": "GB"},
    {"period": "custom", "custom_value": 6, "custom_unit": "hours", "limit_bytes": 2147483648}
  ]
}
```

`limit_bytes` 优先于 `limit_value / limit_unit`。
编辑已有条目时携带查询返回的 `id`，以保留起点和用量；ID 必须属于当前规则且不能重复。
更新时不传限额字段表示保持原配置；`quota_limits: []` 清空配置并自动关闭开关。
同时提交 `quota_enabled: true` 和空数组会被拒绝。
规则字段、限额条目和总开关在同一事务内保存，限额校验失败不修改配置。

规则查询新增 `quota_limits`、`quota_usage` 和 `quota_timezone`。
每项用量包含 `used_bytes`、`reserved_bytes`、`remaining_bytes`、`next_reset_at_local`。
下载记录新增 `queue_reason`、`queue_reason_text` 和 `next_retry_at`。

## 验证

后端使用 `python -m unittest discover -s backend/tests -v`。
新增的 `test_download_quota.py` 覆盖周期、容量、并发和账本；
`test_quota_integration.py` 覆盖真实队列入口、恢复、修改配置与自动调度。
前端使用 `npm test`、`npm run type-check`、`npm run build`。
